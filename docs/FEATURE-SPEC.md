> 本文件记录项目目标功能，作为 Day 3–7 开发依据。
> 规则要求：新增功能先更新本规格，再写代码（见 `.cursor/rules/documentation-and-readability.mdc`）。

| 项目 | 选择 | 说明 |
|------|------|------|

## 2. 任务分类（5 类）

- 日常（默认）
- 学习
- 工作
- 编程
- 运动

创建任务时：
- 用户可在下拉框手动选择分类，默认选中「日常」
- 也可点击「AI 自动分类」，由 AI 根据标题/描述判断分类（Day4 前为 Mock）

---

## 3. 数据模型（Task）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 自增主键（内存阶段用计数器） |
| title | String | 任务标题（必填） |
| content | String | 任务描述 |
| category | enum | 分类：日常/学习/工作/编程/运动 |
| taskDate | 日期 | 任务所属日期，默认今天；用户可通过小日历选择 |
| completed | boolean | 是否完成；新任务默认未完成 |
| createdAt | 时间 | 创建时间 |

## 4. 页面与布局

```
┌─────────────┬───────────────────────────────────┐
│ 左侧分类栏  │ 主区域                             │
│             │                                   │
│ 全部(默认)  │ [任务输入表单：标题/描述/分类]     │
│ 日常        │                                   │
│ 学习        │ [任务列表：按当前选中分类过滤]     │
│ 工作        │   - 任务卡片，可点选               │
│ 编程        │                                   │
│ 运动        │ [选中任务 → AI 分析做法与建议]     │
│             │ [全部任务 → AI 优化日程(1天/多天)] │
└─────────────┴───────────────────────────────────┘
```

- 左侧栏：5 个大类 + 「全部」，默认「全部」显示所有任务
- 点击某分类 → 主区域只显示该分类任务
- 任务输入表单包含日期选择，默认今天
- 任务发布后在任务卡片上显示所属日期；后续会在左下角增加小日历 UI 和动画
- 左侧主导航栏固定在页面左侧，不跟随右侧内容滚动
- 任务卡片可标记完成/取消完成
- 左侧栏包含小日历：当天有未完成任务显示小点；当天任务全部完成后显示小勾
- 点击小日历中的某一天后，主区域只显示该日期的任务
- 第一次点击日期时，小日历展开为整页视图，并显示每天的大致任务标题
- 在展开视图中再次点击当前选中的同一天，小日历收回左侧栏，同时保留该日期任务列表
- 小日历动画和精细 UI 后续在 Bootstrap/美化阶段处理

## 5. AI 功能（两类）

### 5.1 单任务分析（选中某任务）
- 输入：选中任务的标题 + 描述
- 输出：AI 给出「具体做法 + 建议」
- Day4 前：返回 Mock 文本；Day4 起：调用 DeepSeek

### 5.2 日程优化（针对所有任务）
- 输入：当前所有任务
- 参数：安排天数（1 天 或 多天）
- 输出：AI 排出的日程计划草稿
- 交互流程：
  1. 用户选择「优化 1 天」或输入多天数量
  2. AI 生成日程**预览草稿**
  3. 预览区允许用户直接修改内容
  4. 用户确认后，才保存为正式日程
  5. 如果用户不确认，预览不会影响正式日程
- Day4 起：调用 DeepSeek 生成预览草稿；若 API Key 未配置，则显示配置提示

### 5.3 正式日程
- 正式日程来自用户确认后的 AI 预览内容
- 当前阶段先保存在内存中，重启后清空
- 后期接入 MySQL 后可保存为 Schedule 表
